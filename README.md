# 企业知识问答 Agent

- 基于大模型的内部知识库问答系统。
- 要求
	- 模型自己决定怎么检索、读哪篇文档、遇到矛盾怎么办；
	- 代码校验：每条引用必须逐字存在于原文，答案里的每个数字必须有出处。
	- 当上述两条要求不能同时满足时，会被打回

## RUNNING~

```bash
uv venv --python 3.12          # Python ≥ 3.11 都行
source .venv/bin/activate
uv pip install -r requirements.txt
cp env.sample .env         # 写入 LLM_API_KEY ；不填自动进入演示模式
uvicorn kbqa.api:app --app-dir src --port 8000
```

打开 http://127.0.0.1:8000 就能用。右边是模型的决策时间线（每步查了什么、读了什么、为什么），引用可以点开看原文。

## 测试例

页面上有预设用例和知识库切换：

1. **选 C03 问"报销期限是多久"**：D01 说 30 天、D02 说 15 天，两份都没写适用谁 → 模型如实报冲突，列出原文，给出两个可点的确认选项。点一个，接着按确认的制度答（"用户已确认"）。
2. **切知识库到 no_conflict 再问**：D02 没了 → 正常回答 30 天。
3. **问"每周远程办公几天"**：默认库回答 2 天（D05 写了"原办法同时废止"，并把这句话作为裁决依据引用）；切到 no_supersede 把这句话删掉再问 → 变成冲突。同一问题只少一句原文，结论就不同。
4. **开"检索持续失败"再问**：模型重试无效后如实报工具故障，不会编答案。
5. **问"公司明年股价目标是多少"**：库里没有 → 如实说没有资料，不编。

## 原理

模型循环调用三个工具，每一步的理由都会显示在时间线上：

- `search_docs`：分词检索，返回命中段落和它命中了哪些词
- `read_doc`：读原文。只有读过的段落才能被引用
- `submit_answer`：提交答案。代码逐字核对引用是否真在原文里、数字有没有出处、冲突裁决有没有引用依据。不合格就打回，附原因，模型自己改

步数有上限（默认 10），超了返回未完成。文档冲突的处理：原文写了替代或适用范围的按原文裁决；没写的如实报冲突并追问，不擅自选一个。

## 测试与评测

```bash
pytest -q                                          # 60 个单测，不需要 Key
python scripts/run_eval.py --out examples          # 真实模型跑 14 个用例
python scripts/run_eval.py --out examples --perturb # 复测：改掉引用里的数字重跑，看答案变不变
```

本次评测结果：14/14 通过；复测 7/7 答案跟随改动（比如把"工本费 20 元"改成 27 元，答案也会答 27 元）。报告和各用例的完整 trace 在 `examples/` 下。

## 还可以优化的地方

- 数字校验只管阿拉伯数字，中文数字（"三十天"）暂不检查
- 引用对但意思说反的情况（比如把"不享受"说成"享受"）目前拦不住，是下一步
- 词法检索对完全没有字面重合的说法会漏（知识库写"工卡"，用户说"门禁"且没有公共字时会需要改写查询）
