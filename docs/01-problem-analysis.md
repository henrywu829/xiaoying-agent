# 01 问题分析

## 任务要求

- 构建一个企业知识问答 Agent，把"资料检索 → 问题理解 → 判断"写成可观察的 Agent 链路，并满足 6 个要求：明确答案、文档冲突、资料外问题、改写后的相似问题、上下文追问、工具失败。
- 总要求：检索资料支撑回答、可运行可验证（含 trace / eval）、模型自主决策而非固定条件分支。

## 要求

| 要求 | 难点在哪 | 朴素做法会错在哪 |
|---|---|---|
| 明确答案 | 引用要能落到原文 | 模型复述制度名当"引用"，无法核验真伪 |
| 文档冲突 | 要区分"能消解"和"不能消解" | 按文档新旧二选一；或永远报冲突 |
| 资料外问题 | 不能编 | 语言模型先验会编造合理的假制度 |
| 改写后相似问题 | 口语表达没有字面重合 | 词法检索无命中就直接 no_evidence |
| 上下文追问 | "那试用期的呢？"缺主语 | 只拿最后一句话去检索 |
| 工具失败 | 失败要可被模型感知 | 代码自动重试掩盖了模型的处理策略 |

## 关键决策

- **Verify-on-Submit**：`submit_answer` 作为框架的出口，本身是个工具。模型提交后，代码会逐字校验并引用与数字出处。对于错误的内容，会回退给模型修正，这也是 ReAct 的体现。
- **证据记录**：只有 `read_doc` 读过的段落才能被引用；`search_docs` 只返回 40 字预览，不可引用。强迫模型去读完整的上下文。
- **冲突解决办法**（数据+提示词共同实现）：
	- 原文档写明替代/适用范围 → 按依据作答（`resolved_by_doc`，依据也要引用原文）；
	- 没写 → `conflict` + 澄清选项；
	- 用户点选后 → `resolved_by_user`。
	- 通过原文里的声明来判断，而不是 `version_date` 
- **词法检索（bigram + BM25 + 命中阈值）**：口语化问题时检索中的问题，需要模型决定要不要改写并重新搜索。设定一个阈值来决定。每条结果附 `matched_terms`，模型判断命中是否切题。


## 执行路径（以例子说明）

1. C03 → C04 → C05：同一问题，只改知识库（删冲突文档 / 加适用范围）→ 路径与结论都应变。
2. C06 → C13：同一问题，D05 只删一句"同时废止"→ `answered` 变 `conflict`。
3. C01 → C02：同一意图，口语改写 → 多一次改写检索，引用一致。
4. `--perturb`：改被引段落里的数字（20 元→27 元）重跑 → 答案应跟着变。实测见 `docs/03-evaluation.md` 与 `examples/perturb/`。
