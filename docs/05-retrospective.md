# 05 复盘

## 最难的问题

**让"模型自主决策"可验证，而不是看起来在决策。** 固定条件分支也能跑通主流程，但评审点恰恰是"路径要随工具结果变"。解法是三层配合：

1. **证据账本**：`search_docs` 只给 40 字预览、不可引用，`read_doc` 才登记可引用的 `para_id`。这一刀让模型必须真的去读文档，不能拿检索预览凑引用。
2. **Verify-on-Submit**：`submit_answer` 是工具也是出口，guard 逐字校验引用、数字、裁决依据，不合格打回附原因。模型能不能"改对"本身就是决策能力的证据（C05 第一次提交被数字溯源打回，第二次修正通过）。
3. **对照用例**：C06 vs C13（同一文档只删一句"同时废止"→ answered 变 conflict）、C03/C04/C05（同一问题换库 → 三种结论）。如果模型是按启发式或先验答的，对照组应当给出相同答案——实测不同，证明它读的是原文。

## 学到什么

- **校验层比提示词可靠。** "不许编"写进提示词，模型仍会顺手带无出处数字（C05 实测被抓）；写成代码规则就一定能拦住。提示词负责引导方向，边界要靠代码守。
- **词法检索对评测反而更好。** 向量检索会把口语改写直接抹平（"刷的那张卡"≈"工卡"），评审就看不到模型做改写决策。bigram+BM25+命中阈值保留了"检索失败→模型改写→命中"这条可观察路径（C02 是唯一真实用到它的用例，恰好证明它没白写）。
- **工具契约的形状决定模型行为。** `matched_terms` 让模型看见"命中了哪些词"才判断要不要改写；预览长度、note 文案、返回字段名都会影响它下一步选什么。
- **故障要能被模型感知。** 代码里自动重试会掩盖模型的处理策略；把 `note=no_match`、工具异常原样回传，C09（失败一次自行重试）和 C10（持续失败如实报告 `tool_error`）才有区分度。

## 已知限制（和 `docs/02` 一致）

- 数字溯源只核阿拉伯数字，中文数字（"三十天"）不查。
- 引用对但语义说反（"不享受"→"享受"）拦不住，靠提示词+评测兜底。
- 词法检索对零字面重合的说法会漏，改写全靠模型自觉。
